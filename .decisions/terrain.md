# Terrain / World Bake

### bake-architecture — Prebaked layered world; recipe is source, bake is artifact
**Date:** 2026-07-19
**Status:** active
**Decision:** The world is prebaked, not runtime-generated (supersedes the April brainstorm's "no baked worlds" — that rule was scale-dependent and died with the 2,000 km decision). Architecture: layered bake DAG (L0 builders' shape → L7 hand edits) of pure functions with content-addressed caching; per-region compose parameter overrides; coherence via per-layer contracts + bake gates (non-negotiables as computable tests, e.g. see-it-reach-it); runtime adds only bounded detail octaves + deterministic scatter from baked density fields — instances are never data. Git versions generator code + seed + edit deltas; the binary bake is a reproducible build artifact, never committed. Substrate policy: generous interfaces, naive engines — coordinate/tiling scheme and additive-only field registry (LayerBuf) are the over-engineered frozen parts; layer implementations stay naive. Details: docs/terrain.md, docs/terrain/layerbuf-v0.md.
**Why:** Collapses runtime cost on potato hardware (bitmap sample beats noise stack, flat cost), makes authored moment sites edits-to-data rather than procgen coaxing, gives determinism and debuggability (layer bisection), and fits solo+AI development — cheap subagents iterate layer code against hard gates offline. Resolutions, layer count evolution, and all tuning values deliberately unrecorded.

### render-authoritative-placement — Objects/physics sample the SAME height the render uses at that location
**Date:** 2026-07-26
**Status:** active
**Decision:** Anything positioned on the terrain (player, vehicles, creatures, scattered props, physics) must derive its ground height from the *same representation the renderer draws at that location* — either by raycasting onto the actual rendered mesh, or by sampling the exact LOD level being rendered there — never from a separate finer/analytic height function that the render only approximates. Moving things raycast per-frame; static scatter raycasts (or biases) once at build.
**Why:** Terrain will be rendered at continuous distance-based LOD (the render resolution changes everywhere, all the time). If placement reads a finer source than the render, objects sink below or float above the drawn surface — proven concretely in the slice mock, where trees placed on the fine function were buried under the coarser render mesh and the player walked *under* the visible ground ("invisible floor"). With LOD this mismatch is the default state, not an edge case, so placement must be render-authoritative by rule.

### terrain-lod-cdlod — CDLOD quadtree chosen and validated
**Date:** 2026-07-27
**Status:** active (resolves terrain-lod-direction)
**Decision:** Chunked/tiled LOD with a **CDLOD** morphing quadtree, not a geometry clipmap. One shared unit grid per node scaled to node size; the vertex shader morphs odd grid vertices onto even across a distance band so neighbouring levels meet seamlessly; skirts catch residual hairline cracks. Tuned live to morph start 0.90 / end 1.00 on a **horizontal** distance metric (a 3D metric was swamped by camera altitude).
**Why:** The clipmap's headline advantage — few draw calls suiting weak GPUs — was **measured false on the target**. On Intel UHD, 12 vs 67 draw calls performed identically (`mocks/LOD-STRESS-FINDINGS.md`), so the argument for it evaporated. Tiling additionally wins ground-level frustum culling, maps onto the substrate's 128 m tile pyramid, and gives per-tile collision for free. Validated at 240+ fps with ~18k tris and no visible seams.
**Object LOD, same pass:** trees use artist LOD chains (LOD0/1/2 + billboard) distance-bucketed into per-(variant, LOD) MultiMeshes, full geometry only within ~20 m. Naive single-mesh trees cost 5.5M tris at ~1000 instances and dropped the scene to ~8 fps; discard-alpha foliage is far more expensive per pixel than opaque terrain. Each LOD mesh must be normalised to a common height and pivot or switching tiers visibly resizes/jumps the tree.

### splice-tiling — Real-world DEM splices tile the ring in three resolution tiers
**Date:** 2026-07-29
**Status:** active
**Decision:** The ring's surface comes from real-world DEM splices placed around the arc at their `docs/geography.md` positions, in **84 km patches** (36 tile the 3,000 km circumference; the patch already spans the full 50 km width, so tiling is along the arc only). Height *and* Sentinel-2 imagery are fetched per patch by `tools/dem/pipeline.py`. Sampling is three-tier, in priority order: (1) the patch the camera is standing in, streamed at 1536² on a worker thread; (2) all patches at 512² in a `Texture2DArray`; (3) procedural noise only where no patch exists.
**Why:** One DEM tiled everywhere made 3,000 km read as a single repeated valley. Full resolution for every patch is ~2 GB and pointless — you only ever stand in one. The tiers put the detail where the player is and spend almost nothing on scenery they fly past. Streaming is threaded because decoding a 3584² u16 heightmap is a multi-million-iteration loop that would hitch on every patch crossing.
**Gotcha (cost a real bug):** patches whose data isn't fetched are skipped at load, so **loaded-patch indices do not line up with the authored `PATCHES` list**. Indexing the authored list with a loaded index silently loads the wrong location's file and the wrong biome — it made 6 of 10 streams fail while looking fine in the log. Everything downstream goes through parallel arrays built at load time. Caught only because `--selftest` exists; add coverage before trusting anything index-mapped here.
**Ocean:** implemented by clamping terrain to sea level in the shader rather than drawing a water plane — no second mesh, no z-fighting against the seabed, and the clamp yields a flat surface with flat normals for free. CPU height clamps identically, per render-authoritative-placement.

### void-is-not-sea — Off-patch void reads as dry land, never ocean
**Date:** 2026-08-10
**Status:** active
**Decision:** A terrain sample with no real data behind it — outside the home DEM and every splice patch, i.e. the procedural fallback — is **not sea**, regardless of its value. Ocean exists only inside real patch/DEM data. Encoded in the sea *test*: `_sea_depth` returns dry (-1) for any point that fails `_has_terrain_data` (home DEM in bounds OR a patch owns it), before it ever probes for a shore.
**Why:** Terrarium floors its tiles at 0 m, and the off-patch procedural fallback is `maxf(noise,0)·DISP` whose low half sits below SEA_LEVEL — visually and numerically identical to real coastal water, but nothing is there. The old `_sea_depth` walked outward for a shore, found none (there is none in the void), and returned SEA_MAX_DEPTH: it "found" 12 m of ocean by walking off the data, which silently broke the sea-framing search and would float a boat on empty space. The one thing that separates real sea from the phantom is whether *any data* backs the sample, so that — not a value threshold or a distance-to-shore heuristic — is the discriminator.
**Scope / not-done:** Fixed on the authoritative CPU test side (`_sea_depth`, and through it the framing search and boat grounding). The far band shader draws no water at all, so "ocean to the horizon" is bounded to the CDLOD bubble's inter-patch procedural gaps; aligning the GPU `sample_h`/`is_water` clamp and `_terrain_h`'s placement clamp to the same predicate is deferred to a shot-verified pass (the Godot binary is out-of-repo here, so a render change can't be eyeballed). Retire the whole synthetic-shelf/void distinction the day a bathymetric source lands (see the `_sea_depth` note).

### synthetic-seabed — The seabed is generated from the coastline, not sourced
**Date:** 2026-08-10
**Status:** active
**Decision:** There is no real bathymetry anywhere on the ring — Terrarium floors its tiles at 0 m, so 87 % of a coastal patch is exactly 0.0 and the sea floor is a flat plate under the clamp. The submersible needs somewhere to descend to, and the choice was GEBCO (an external download) or synthesis. **Synthesise it**, consistent with everything else this project generates rather than sources (houses, hedges, palms, textures — and the species-variety item, unblocked the same way). `_sea_depth` builds the floor from data that IS real, the coastline: the shore-distance probe gives the shallow-near-beach → deep-offshore trend (`SEA_MAX_DEPTH` at the shelf edge, falling toward `SEA_ABYSS` past it), and `_noise` lays banks and trenches (`SEA_RELIEF`) over it so there is varied ground to explore, not a smooth bowl. Near-shore values are unchanged (boat grounding untouched); the abyss and relief fade in with offshore distance.
**Why:** GEBCO adds an external, licence-bound, gitignored data dependency to a project that pointedly has none, for a floor the player only ever sees from inside a submersible in murky water — synthesis is cheaper, deterministic, and self-calibrating to each patch's own coastline. It is not real bathymetry (no named trenches, no true shelf break), but it gets the property that matters: a descendable, varied floor keyed off real coastline data. Supersedes the "retire the synthetic shelf when a bathymetric source lands" note in [[void-is-not-sea]] to the extent that the shelf is now the *intended* long-term model, not a stopgap — a real source would refine it, not replace the approach.

### terrain-lod-direction — Camera-relative continuous LOD with seamless transitions
**Date:** 2026-07-26
**Status:** SUPERSEDED 2026-07-27 by terrain-lod-cdlod
**Decision:** The real terrain needs camera-relative, continuous LOD — clipmap (concentric sliding resolution rings) or distance-driven quadtree — with crack-free transitions between levels (shared edge verts or skirts). Not the mock's fixed fine-centre/coarse-flank tiers (world-stuck, hard seam). Clipmap-vs-quadtree is open. Ties to the substrate resolution pyramid (docs/terrain/substrate.md) and R2 curvature (docs/research/r2-ring-curvature.md). The `game/mocks/ring_vibes` mock is the working basis for prototyping this — preserved on the `terrain-lod` branch.
**Why:** Fine detail near the camera, cheap far, following the player — the standard requirement for a walkable world at ring scale on potato hardware. Recorded now because the mock surfaced the requirement concretely; the specific technique is a real implementation-pass decision, deliberately left open.
